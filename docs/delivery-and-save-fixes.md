# 预发布后的交付与保存优化

本次交付与保存修复的固定开发候选为 `c5259c4`，当时已完成本机安装验证。后续上手改动见 [文档导航](README.md)。已发布的 `v0.1.0-alpha.1` 附件仍固定为原被测包；两者不混用验收成绩。校验与测试范围见 [开发候选清单](development-candidate.json)。

## 交付入口

过去保存命令只返回相对 PNG 名称，宿主可能据此拼出无法使用的链接。现在 CLI append 在保存与校验完成后额外返回 delivery，其中包含指定版本、完整文件路径及可直接使用的预览/下载 Markdown；版本记录 schema 和 Python append 的返回约定保持兼容。

只读 delivery 命令可重显已接受的指定旧版，无须读取原图、外发、生成或追加版本。中文、空格、括号和特殊字符路径经编码处理；缺失版本/文件拒绝交付。入口展示失败后重取链接，不重复保存成新版本。

`d2085e7` 的三个干净 Codex 会话验证长原话旧作品、特殊路径旧版及缺失版本，均通过，零生成、既有文件哈希不变。该验证包含回复链接解析和目标文件检查，不等于对所有客户端点击/渲染的保证。后续 c5259c4 只调整保存归属逻辑，链接逻辑未变；最终包另用一个干净会话重显长原话旧作品通过，仍为零生成、文件哈希不变。

## 保存中断与文件归属

发现并复现：PNG 已发布而记录提交失败时，原清理逻辑可能误删被另一写入者替换的同名文件。最初在发布后读取 inode 的修补仍有过早替换窗口，复审指出后已撤回这种判断方式。

最终由导出层从发布前的暂存文件取得设备号和 inode，返回归属凭据；保存层在发布后与提交记录前检查，检测到替换就拒绝接受。失败清理只处理仍匹配自身凭据的文件，未知状态保留并报告原错误。旧记录和版本不变。覆盖两种替换时机的受控 OS 边界测试已先复现失败再通过；不宣称可抵御任意恶意并发写入或操作系统强制终止。

38 项确定性测试及类型检查在本机 CPython 3.11、3.12、3.13 通过，仓库检查、固定提交重建、独立安装/自检/卸载通过。Standards 与 Spec 定向复核无剩余问题。

## 尚待优化

这轮解决交付与保存缺陷，没有修复纯生成的人物保真、小字或密集构图能力，也没有将旧完整矩阵的 11/18 改成新候选通过。历史首次失败和人工评分缺口保留。下一步优先验证实际低照人物与中文可读性；不能靠重复抽样凑通过，也不能擅自改为本地文字层。
