# 发布验收执行方法

依据 #17、#26 和已确认的 [完整验收合同](../prototypes/acceptance/acceptance-proposal.md)。目前未通过，计划本身不算证据。

## 固定候选与私密证据

先固定提交和允许名单 ZIP 的 SHA-256。从该包干净安装，记录 Codex、操作系统、Python、Pillow、HEIF（如适用）、图像服务及可获取版本；服务版本不可获取时明确填写 unavailable。发现、显式调用、自动选用、生成、修改、恢复须在目标宿主实际执行；独立目录脚本运行不能代替这些证据。

用 `scripts/evaluation.py init <仓库外新文件> --commit <40位提交> --package-sha256 <64位哈希>` 创建 18 个未测首次尝试。初始化文件权限 0600；源图、成图、场景、文字、提示词与真人详细评价均保存在仓库外。`summary` 输出只含候选标识、数量和门槛状态，不输出私人路径/文字/评分细节。

## 样本和生成

固定六张合成图 synthetic-01…06，使用清单中原文件和场景；real-01…03 可以由用户提供/指定，或按用户授权自行寻找许可清楚的日常照片：近景、双人关键互动、4–6 人密集场景，至少一张人物仍可辨认的低照/压缩图。不能只挑精美样片，也不强索未成年人素材。每个输入在干净会话首次生成两轮，合计 18；缺照片或能力保留 untested/unsupported，不缩分母。

每条记录 sample、round、attempt、服务是否真实、是否干净会话、交付核验结果、状态、是否误交付、真人评审者、五项分数、耗时、可获取成本与失败原因。后续重试追加 attempt>1，保留首次记录不变。源 SHA-256、授权、所用包和环境须附在私密会话证据中；不把摘要字段当作独立证明。

可用 `scripts/host_session.py --codex <宿主二进制> --case <私密请求计划> --destination <仓库外新目录>` 执行真实宿主测试。计划固定源路径/哈希和请求；每次启动无历史的 ephemeral 会话，检查已安装包清单，保留实际图像工具事件及失败。它只记录行为，不替人判定画面。受控服务替身只用于异常测试，记录中的 `image_calls` 与 `tool_requests` 分开，不能混为真实生成。

用户要求最后集中审阅时，先执行完整生成、逐图核验及行为测试。真实服务、干净会话、Delivery Verification 已通过而尚无真人评分的尝试记为 `awaiting_review`，不记未测，也不算发布通过。原始失败和未通过候选保留，不能被后来的重试覆盖。

## 逐图和真人评审

先完成 Delivery Verification，再由产品负责人对照原图看完整成图以及 390 CSS px 宽手机视图（不缩放），逐项打分：composition、chinese_typography、atmosphere、narrative、save_share_value。1 明显失败，2 需大改，3 平庸或明显缺陷，4 完成度高愿意保存，5 出色。每项至少 4，不以平均分抵消低分，不用代理自评代替真人。

至少 16/18 首次尝试同时通过，而且九个输入各至少成功一次；任何错误或未核验结果被误交付都阻止发布。合成图不能证明真人保真，小样本不是通用成功率保证。三项定向修改与 [十五类行为矩阵](../tests/cases.md) 都须通过。

## 变更与重测

运行文件或提示约束变更会产生新候选，旧成绩不能移用；按同一矩阵重评新候选。只有不影响运行行为的报告补充才可沿用已固定包的检查。将统计摘要写入公开报告前人工复核私人资料是否被带出。验收通过后仍要做许可、历史和发布前检查，不自动公开。
