# 发布验收执行方法

当前源码以 Plog 场景与各 Agent／provider 组合分别验收。历史人物矩阵源于 #17、#26 的 [旧版验收合同](../prototypes/acceptance/acceptance-proposal.md)，保留为回归，不代表新范围已通过。

## 固定候选与私密证据

先固定提交和允许名单 ZIP 的 SHA-256。从该包干净安装，记录 Agent 名称和版本、读图服务、操作系统、Python、Pillow、HEIF（如适用）、图像服务及可获取版本；服务版本不可获取时明确填写 unavailable。发现、显式调用、自动选用、生成、修改、恢复须在目标宿主实际执行；独立目录脚本运行不能代替这些证据。

用 `scripts/evaluation.py init <仓库外新文件> --commit <40位提交> --package-sha256 <64位哈希>` 创建 Plog 的 14 个未测首次尝试；显式 `--suite people-v1` 才创建历史人物 18 次矩阵。初始化文件权限 0600；源图、成图、场景、文字、提示词与真人详细评价均保存在仓库外。`summary` 输出只含候选标识、数量和门槛状态，不输出私人路径/文字/评分细节。

## 当前 Plog 矩阵

用 `--suite plog` 为每个 Agent／图像服务组合单独建证据。固定 landscape、street、still-life、pet、people、crowd、series-photo 七类，每类两轮共 14 次；包含无人山海、城市街道、食物静物、纯宠物、人物、超过六人的人群，以及一组 Plog 中需保持系列连贯的照片。各类原图来源清楚并有对应处理授权，不能用人物合成夹具替代无人实拍。

全 14 次首次尝试通过、20 类行为与三类修改通过、无误交付且环境资料完整，才标该组合通过。环境字段为 agent、agent_version、vision_service、platform、python、image_service、service_version_or_unavailable。某组合通过不代表其他 Agent 或服务通过。系列顺序、逐张版本和部分失败状态另按行为用例验证。

## 历史人物矩阵（people-v1）

固定六张合成图 synthetic-01…06，使用清单中原文件和场景；real-01…03 可以由用户提供/指定，或按用户授权自行寻找许可清楚的日常照片：近景、双人关键互动、4–6 人密集场景，至少一张人物仍可辨认的低照/压缩图。不能只挑精美样片，也不强索未成年人素材。每个输入在干净会话首次生成两轮，合计 18；缺照片或能力保留 untested/unsupported，不缩分母。

每条记录 sample、round、attempt、服务是否真实、是否干净会话、交付核验结果、状态、是否误交付、真人评审者、五项分数、耗时、可获取成本与失败原因。后续重试追加 attempt>1，保留首次记录不变。源 SHA-256、授权、所用包和环境须附在私密会话证据中；不把摘要字段当作独立证明。

Codex 环境可用 `scripts/host_session.py --codex <宿主二进制> --case <私密请求计划> --destination <仓库外新目录>` 执行真实宿主测试。计划固定源路径/哈希和请求；每次启动无历史的 ephemeral 会话，检查已安装包清单，保留实际图像工具事件及失败。它只记录行为，不替人判定画面；该工具专用于 Codex，不能拿它产生其他 Agent 的通过记录。其他宿主保留其原生会话事件和交付证据。受控服务替身只用于异常测试，记录中的 `image_calls` 与 `tool_requests` 分开，不能混为真实生成。

用户要求最后集中审阅时，先执行完整生成、逐图核验及行为测试。真实服务、干净会话、Delivery Verification 已通过而尚无真人评分的尝试记为 `awaiting_review`，不记未测，也不算发布通过。原始失败和未通过候选保留，不能被后来的重试覆盖。

## 逐图和真人评审

先完成 Delivery Verification，再由产品负责人对照原图看完整成图以及 390 CSS px 宽手机视图（不缩放），逐项打分：composition、chinese_typography、atmosphere、narrative、save_share_value。1 明显失败，2 需大改，3 平庸或明显缺陷，4 完成度高愿意保存，5 出色。每项至少 4，不以平均分抵消低分，不用代理自评代替真人。

历史 people-v1 至少 16/18 首次尝试同时通过，而且九个输入各至少成功一次；任何错误或未核验结果被误交付都阻止发布。合成图不能证明真人保真，小样本不是通用成功率保证。三项定向修改与对应 [行为矩阵](../tests/cases.md) 都须通过；Plog 使用上文的 14/14 和新增场景／宿主行为要求。

## 变更与重测

运行文件或提示约束变更会产生新候选，旧成绩不能移用；按同一矩阵重评新候选。只有不影响运行行为的报告补充才可沿用已固定包的检查。将统计摘要写入公开报告前人工复核私人资料是否被带出。验收通过后仍要做许可、历史和发布前检查，不自动公开。
