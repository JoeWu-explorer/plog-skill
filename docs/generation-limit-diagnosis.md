# 生成约束的诊断与处理边界

> 后续交付决定：所有者已授权合并、推送、预发布和更新 issues。本次为私有仓库中的 `v0.1.0-alpha.1`，不改变公开可见性、不代表完整验收通过。下文未执行发布的叙述保留为此前检查时的状态；当前交付见 [预发布说明](prerelease-alpha-1.md)。

当前保留的安装包仍是 `2a6156c`，新的完整 18 次首次生成只有 11 次通过底线、7 次拒收，三张实拍均两轮失败。新增的 `142b30e` 提示规则经过完整实测后撤回，不能作为已修复版本交付。

## 已完成的反例验证

`142b30e` 用同九张输入完成 18 次首次生成，9 次被接受并通过独立检查，9 次被拒收。三种自然语言修改另有三次成功，每次一次真实调用、原版本哈希保持。该批次的人工分数为空，且未达到发布门槛。

新增规则要求普通旁白的可见字形在 390 CSS px 视图中约为 20–24 px，并要求低照人物区不做增强。实际服务提示词确实包含这些要求，但近景实拍仍返回约 11–12 px 的文字。部分宿主又将设计目标当成硬门槛；规则变严格没有改善生成本身。

六人场景分别要求完整等比摄影区与新增文字区分开，实际仍出现重新构图或裁掉前景手臂。低照图仍可能补出原图无法核实的面部结构。失败均未登记为可交付版本。这证明拒收保护在这些实例起作用，不能证明生成质量问题已修复。

工程处理是撤回这六段新增指导，恢复到 `2a6156c` 的逐字节相同运行内容。新增宿主回归用例保留。撤回候选的故障测试完成首次六类、修改六类和两次超时调用后，停止了下一项重试试验；部分事件保留，不计完整十五类通过。最终保留包已另行完整重测，不沿用撤回候选的结果：18 次首次生成、三次自然语言修改、17 次受控故障调用、七个零生成边界会话和三个实际补充行为会话。三种修改通过；长原话成图虽合格，首次回复仍用了相对下载链接，所以十五类行为仅计十四类通过。

## 为什么不能直接宣称全部完成

本任务使用的图像工具通过提示词和参考图执行生成式编辑。提示词表达“只改文字区”并不形成可验证的摄影像素锁定；改变目标字号也不能保证输出实际字高。继续增加同义禁止语句，或重复生成直到凑够好图，均不足以证明可靠性修复。旧失败不能被重试覆盖。

已确认产品路线要求照片、光色和中文整体经内置图像服务生成，禁止用本地贴字冒充成图。因而不能未经产品范围调整，偷偷换成保留原像素的本地排版，或换外部图像服务来掩盖当前限制。

## 可讨论的范围调整

最终保留包未达到首次成功门槛，需要产品路线决策，而非让人工给失败图补高分：

- 保留纯生成路线：继续提供核验失败提示与用户发起的单次重试，明确不能承诺密集/低照图首次成功；这需要重新决定发布范围，不能擅自降低原验收合同。
- 允许受控文字层：逐图艺术指导仍由模型完成，但摄影区域和中文排版由可验证的渲染流程保护。它改变“整体生成、禁止本地排版”的原约束，需要明确授权后另行实现和验证。

当前两种范围调整均未执行。公开、推送和 issue 关闭也未执行。
