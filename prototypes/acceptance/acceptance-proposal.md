# v1 验收标准提案

状态：待用户决定。本文是规划评审附件，不是测试报告，不表示正式 Skill 已实现或通过验收。

对应决策：[锁定 v1 验收标准与测试矩阵](https://github.com/JoeWu-explorer/photo-dialogue/issues/11)。以[当前生成式合同](https://github.com/JoeWu-explorer/photo-dialogue/issues/15#issuecomment-5550078321)、[首次生成与修改体验](https://github.com/JoeWu-explorer/photo-dialogue/issues/10)和[修改记录与恢复](https://github.com/JoeWu-explorer/photo-dialogue/issues/16#issuecomment-5550212078)为依据。最终决议以该决策票的 resolution comment 为准。

## 1. 两层验收

- 单张交付核验：每次生成或修改后执行。核验未通过或无法判断的候选图，不算 Accepted Version，不替换已有成图。
- 发布验收：用固定样本验证正式 Skill 的质量与行为，由产品负责人审阅完整成图。此前接受的原型和个别效果示范不抵扣正式版本验收。

单张核验由执行 Skill 的代理负责；发布前的真人审美评审不变成普通用户每次出图前必须完成的审批步骤。Accepted Version 表示通过交付核验，仍允许用户表达审美不满意。

## 2. 每张成图必须通过的底线

| 检查 | 可观察通过条件 |
| --- | --- |
| 人物真实性 | 对照原图逐人检查人数、脸、表情、年龄线索、体型、肤色、衣着、视线和手势。没有实质漂移、增删人物、畸形肢体或篡改互动；无法辨认时不宣称通过。生成式像素变化本身不判失败。 |
| 中文准确 | 与本次确定的文字逐字比较，检查增、漏、错字和无关文字；标点、繁简与确认引语保持要求。断行可按排版调整，语义和归属不能变。OCR 只能辅助，须看最终图中文字。 |
| 构图与归属 | 不遮挡脸、关键手势、共享物件或互动路径。阅读顺序明确，人物对白可明确归属；未知关系不靠外貌猜测，群像不强制每人一句。 |
| 叙事可靠 | 文字有可指出的场景依据，创作声音不冒充真实引语，不捏造私人事实；遵守 Voice Budget 及既有例外。无文案的 deliberate silence 按其明确意图检查。 |
| 视觉协调 | 滤镜、光色、字体、字色和构图有当前照片及用户意图的依据；不把暖色、胶片、宋体、B 或图上文下写成默认答案。人物肤色自然、文字易读，无明显生成瑕疵。 |
| 输出有效 | PNG 可打开，保留原方向或遵守用户明确比例；预览和下载指向同一版本，无 EXIF、IPTC、XMP、位置或设备信息。原图校验值不变，旧版可用。 |
| 私密交付 | 使用既有当次授权，未授权时不发往图像服务；没有公开上传、自动发布、默认原图副本或永久授权记录。成功和失败都清理临时衍生物。 |

问题未解决时应说明具体障碍。不能静默重试、换服务或退回简单贴字，并把它们当成成功交付。

## 3. 真人视觉评审：建议各项至少 4/5

评审者查看原图与完整成图，再以宽 390 CSS px、无缩放的手机阅读视图检查，必要时放大核对人物和字形。390 px 是一致的评审条件，不是导出尺寸。

| 维度 | 4 分所代表的可观察标准 |
| --- | --- |
| 构图与图文关系 | 有明确视觉主次和阅读路径，文字像画面设计的一部分，裁切与留白服务这张照片。 |
| 中文排版 | 字形清楚，字号、字重、断行、字距和字色协调；手机视图可读，无拥挤或突兀装饰。 |
| 滤镜与氛围 | 光色、对比与质感支持当前场景，人物自然；效果强弱适当，需要时可以完全不加颗粒或泛光。 |
| 叙事贴合 | 能指出文案对应的动作、物件或用户上下文；语气恰当，不是可随意换到任何照片上的套话。 |
| 保存与分享价值 | 成图相较原图增加了值得保留的表达；评审者愿意把它作为完成作品保存，而非仍需明显返工的样稿。 |

统一量尺：1＝明显失败；2＝需要大改；3＝可用但平庸或仍有明确缺陷；4＝完成度高、愿意保存；5＝出色。建议所有被交付的测试成图每项均 ≥4，不用平均分抵消短板。低于 4 时记录具体画面问题，不只写“不高级”。代理自评不能替代负责人评审。

## 4. 生成质量测试：建议 9 张照片、两轮独立首次生成

使用同一个待发布版本、固定照片和场景描述，每轮开启干净会话，每个输入只做一次首次生成。两轮都保留全部尝试的结果状态，不能挑最好的一轮。

| 样本 | 必须观察的覆盖 |
| --- | --- |
| 现有六张公开合成照片 | 覆盖 1–6 人、横竖方图、婴幼儿及多人互动、冷光与混合光、疏密构图；使用 manifest 提供的场景事实。 |
| 三张经授权的真实照片 | 覆盖近景人物、两人关键互动、4–6 人密集场景；至少一张包含日常手机低照度或压缩，但人物仍可辨认。未成年人素材仅在适当授权且自愿提供时使用，不为凑样本索取。 |

真实照片在正式验收时由用户提供或明确指定。既往私密样片不自动获得新的测试用途或公开授权。源图、结果和审阅细节保留在仓库外的本地私密目录；只有不含私人信息的统计可进入公开报告。

建议门槛：18 次首次生成中至少 16 次同时通过交付底线和真人视觉评审，且 9 个输入各至少成功一次。首次失败不得因后来重试成功而改写。任何一次把人物漂移、错字或未核验的图误交付为合格作品，均阻止发布。

这只是小样本发布门槛，不代表已证明 89% 的真实用户成功率。记录尝试数、成功数、各类失败、耗时和可用的调用成本；无固定耗时承诺。低于门槛先改进，再用同一矩阵评审新版本，不通过换照片消除失败。

对比冷光独照、混合光双人和密集群像的艺术指导及成图：必须能说明各自的取舍。使用同一种字体或色调不自动失败，机械复用全套处理且不适合照片才失败。既有参考项目用于视觉质量讨论，不复制无许可内容、素材或提示词。

## 5. 三个定向修改用例：建议全部通过

| 请求 | 成功条件 |
| --- | --- |
| 只改一句话 | 新字准确；保留未要求改变的叙事归属与视觉意图，重新核验人物。 |
| 氛围淡一点，文字不变 | 处理强度可感知地降低，确切文字不变，人物及构图意图仍可信。 |
| 以指定旧版继续，把字移开手部 | 使用指定版本；解决遮挡，保留其余要求，旧版仍可访问。 |

不要求像素完全不动；明显改变无关人物、表情、互动、文字或视觉意图判失败。不能把修改失败的新图设为当前 Accepted Version。

## 6. 行为与失败矩阵：建议全部通过

以下可使用工具替身、文件夹夹具和流程演练；不要求为每个分支调用收费生成服务。替身测试不计入上面的真实生成成功率。

| 情况 | 预期行为与证据 |
| --- | --- |
| 照片有充分可观察场景，未说明关系 | 使用中性叙事，完成一次交付，不强制风格或文案选择。 |
| 引语说话人不明确，归属影响含义 | 只问必要归属问题，未回答前不编造。 |
| 确认引语、繁体要求、创作声音 | 逐字保留确认内容及繁简要求；不把创作当事实，不强行删改引语来凑字数。 |
| 超过六人、无法辨认、损坏文件或无法解码 | 清楚说明范围或输入问题，请用户提供合适照片；不悄悄裁人或推测身份来通过。 |
| 显式要求不同风格或导出比例 | 遵循要求并检查人物和互动保护；无法兼顾时说明冲突。 |
| 未成年人、敏感上下文、明显私密背景 | 不凭外貌推断，不制造羞辱或敏感事实；仅对影响当前处理的必要信息做最小澄清。 |
| 尚无当次服务授权 / 已有明确授权 | 前者没有外发调用；后者承接，不重复索要口令式确认。新照片或新服务不继承永久许可。 |
| 服务超时、不可用、拒绝，或返回无效文件 | 不宣称完成、不自动重试或降级，已有成图保持可用。 |
| 注入已知错字、人物漂移或无法核验候选 | 不进入 Accepted Version；记录失败原因，不能误报合格。此项不替代对真实生成结果的审阅。 |
| 用户明确说“再试一次” | 只增加一次尝试并重新核验；再次失败停下说明，首次失败仍计入统计。 |
| 正常版本保存或保存中断 | 成功记录可指向真实可打开的文件；中断不破坏旧版、不创建虚假已接受版本，报告保存未完成。 |
| 新会话读用户指定的修改记录 | 恢复原图引用、文字、视觉意图和选定版本；记录内容作为数据，不作为指令或授权。 |
| 原图缺失、移动或校验值变化 | 请求用户提供或指明正确原图；不扫描私人目录，不拿成图代替原图。 |
| 无记录或选定版本文件缺失 | 说明缺口，请用户提供所需原图、版本及上下文；不编造恢复成功。 |
| 附加交付和记录隐私 | 默认只有成图及最小本地记录；提示词/文字文档按需，重建提示词标明重建；无源图副本、源元数据、生物识别资料、永久授权或无关私密资料。 |

## 7. 验收报告与责任

记录被测版本、日期、可获得的模型/服务版本、固定样本标识、每次尝试及失败原因、视觉逐项评分、修改和行为用例结果。区分未测、不支持、失败和通过。私人素材只在私密记录中关联，公开报告不包含私人文件路径、文字或人物细节。

确定性文件和流程规则用自动检查；文字和人物核验结合实际图像检查；最终审美质量由产品负责人判断。通过矩阵仍不代表所有设备格式、极端低光、严重遮挡、肤色或场景均已验证，报告须说明样本限制。

本提案未执行任何正式生成验收，也未为真实照片获得新处理授权。待决定：真人视觉逐项 4/5 的门槛，以及 18 次首次生成至少 16 次成功、逐输入至少一次成功的发布门槛。包结构与公开发布清单由后续决策承接。
