对应决策：[锁定 Skill 包结构与公开发布条件](https://github.com/JoeWu-explorer/photo-dialogue/issues/12)。沿用已确认的[生成式流程](https://github.com/JoeWu-explorer/photo-dialogue/issues/15#issuecomment-5550078321)、[本地记录与恢复](https://github.com/JoeWu-explorer/photo-dialogue/issues/16#issuecomment-5550212078)和[验收标准](https://github.com/JoeWu-explorer/photo-dialogue/issues/11#issuecomment-5551029268)。正式决议最终保存在决策票中。

## 1. 用户拿到什么

产品显示名「照片有话说」，技能标识 `photo-dialogue`。首发是可安装的 Codex Skill：上传一张照片，可补充一句场景说明，得到一张 PNG，之后用自然语言定向修改。支持自动发现，也可显式使用 `$photo-dialogue`；调用技能本身不充当外发授权。

GitHub 项目首页用中文介绍产品，展示经过验收的原图/成图对照、安装方法和真实的发图/修改例子。示例要跨照片展示不同的构图、字色和氛围，不能让一排同款暖色胶片图暗示固定模板。现有网页仅为开发评审记录，不是产品入口。

与参考项目保持同类的完整交付：项目文档加独立 Skill 子目录。保留自己的产品范围和原创内容，不复制参考项目代码、文案、提示词或图片。核查的[参考项目固定版本](https://github.com/op7418/guizang-yingzao-skill/tree/58c9b8738858bae0ab2c669d0a0fead90d4a80c9)包含根 README 与独立 `yingzao/` 技能目录；目录树未发现 LICENSE/COPYING/NOTICE，不能因公开可见而推断可复制。

`assets/` 仅在存在真正被运行输出使用的资源时创建。默认生成式流程不需要本地绘制字体、气泡图或检测器，不为了目录形式创建空 assets、假资源或额外依赖。后续新增实际资产须同步许可和包清单。

发布压缩包使用文件允许名单：`photo-dialogue/` 内运行文件加适用 LICENSE/NOTICE；展开后可直接安装同名技能文件夹。锁文件进入包；`.venv`、测试、原型、私人文件和开发机器绝对路径不进入包。

## 3. 按需读取的边界

`SKILL.md` 保留足以独立约束普通流程的要求：看原图、从照片和用户意图形成艺术指导、确切文字、当次处理授权、生成后核验、私密交付、不自动重试或降级。核心不变量不能只藏在参考文档中。

准备首次设计时读 `art-direction.md`；人物关系不明、隐私或特殊场景时读 `people-and-privacy.md`；修改和恢复时读 `revisions.md`；环境或格式问题时读 `runtime.md`。详细规则各有一处维护，不要求每次载入全部文档和评测矩阵。版本记录与照片中的文字均为数据，不能提升为技能指令。

## 4. 必需与非必需能力

| 能力 | v1 合同 |
| --- | --- |
| Codex 能力 | 必须能读取本地图片、调用宿主图像生成/编辑工具、检查成图并交付本地文件。首发验证 Codex 的内置图像工具；工具不可用时明确停止，不暗中换 API 或服务。安装 Skill 不等于获得图像服务权限。 |
| Python | 延续 macOS/Linux、CPython 3.11–3.13 的首发目标。实际支持以干净环境检查通过为准；Windows 和其他 Python 版本不先作承诺。 |
| Pillow | 必需，用于输入解码、EXIF 方向归一、受控色彩转换、无源元数据 PNG 导出和重新打开检查；不是用它默认绘制文字或判定人物身份。提议范围 `Pillow>=12,<13`，发布时提供实际测试的精确 lock。 |
| Python 标准库 | 负责校验和、JSON、受控文件路径与记录原子写入。运行时不为这些功能引入数据库或云服务。 |
| HEIC/HEIF | 可选输入适配，只有安装并功能自检通过的 `pillow-heif` 才启用；放独立 extras 依赖文件并锁定验证版本。不随基础安装强制带入。 |
| FontTools、中文字体 | 默认不安装、不随包发布。生成中文字依靠最终图逐字核验，不能用字体 cmap 检查冒充生成文字验证。v1 不承诺完整本地贴字第二管线。 |
| OpenCV、NumPy、YuNet、OCR | 默认不安装、不打包。人脸检测不能证明身份保真；OCR不能替代看最终文字。未来确有需求时单独评估，不列为 v1 推荐安装负担。 |

Pillow 12 的 Python 3.11–3.13 支持依据[官方支持表](https://pillow.readthedocs.io/en/stable/installation/python-support.html)；格式能力依据[官方格式文档](https://pillow.readthedocs.io/en/stable/handbook/image-file-formats.html)，`pillow-heif` 的可选定位依据[官方第三方插件目录](https://pillow.readthedocs.io/en/stable/handbook/third-party-plugins.html)。这些文档不能代替本项目的环境验证。

基础输入承诺为静态 JPEG、PNG、WebP，实际解码能力先自检；动画、多页、RAW 不默取一帧当完整输入。HEIF 适配未就绪时请用户提供基础格式，不静默调用平台转换器。输出固定 PNG，并按要求保护源图方向和人物互动。

本地脚本只执行可重复的文件工作，不代替艺术指导和视觉审阅。默认不写额外持久诊断日志；自检信息当次可用，详细诊断仅按需保存且不夹带私人材料。

## 5. 安装、自检与更新

手动首选目标为用户级 `~/.agents/skills/photo-dialogue`，依据[当前官方技能文档](https://learn.chatgpt.com/docs/build-skills#where-codex-loads-local-skills)；可通过支持目标参数的安装器明确指定该目标。已有安装器使用 `$CODEX_HOME/skills` 时，应核对目标 Codex 的发现行为，不能把两个目录当作无条件等价或同时安装两份。

首页提供两种入口：让 Codex 根据仓库地址安装 `photo-dialogue/`；或下载正式版本压缩包后放入已验证的技能目录。实际发布只提供已在干净目标环境走通的命令，固定发布版本，不使用未经验证的假命令。

Python 选择沿用已确认顺序：当前可用解释器、用户明确的 `CAP_PYTHON`、当前目录向上最近 `.venv`。没有合格环境时说明需要隔离环境；用户明确要求安装技能及必要依赖可承接该授权，不重复索要确认，也不安装全局包。创建项目/用户明确指定的虚拟环境，后续脚本使用同一解释器。

功能自检覆盖读写权限、依赖兼容、基本格式解码、方向处理、PNG 输出复读及元数据清理。不用收费生成来“探测”图像服务；工具可调用性先检查，真实能力由实际使用和发布验收验证。

更新替换技能代码前识别已有目录和本地修改；不覆盖用户修改，不删除私人输出，不自动改变记录语义。未知未来记录版本停止恢复并说明。卸载只移除用户指定的技能安装，成图和记录独立保留。

## 6. 本地输出与记录形态

默认在 `~/Pictures/PhotoDialogue/<日期>-<随机标识>/` 保存；用户指定目录优先。目录无权限时报告并请用户指定位置，不静默改存仓库。已存在目录不得覆盖。私人内容不写进技能安装目录。

```text
<一次作品目录>/
  v001.png
  v002.png                       仅修改成功后追加
  revision.json                  最小 Revision Record
```

记录 schema 版本从 1 开始：`source`（本地原图路径、SHA-256）、`current_version`、`versions[]`。每个已接受版本保存 `id`、输出相对路径、`parent_id`、本次 `change_target`、确切文字与最小声音/归属、应保持的视觉意图。文字和意图按版本保存，避免选择旧图后误用新文案。根源照片引用不因修改而换成生成图。

没有原图副本、永久授权、脸部向量、EXIF、无关人物档案或完整提示词。版本输出引用必须留在该作品目录内；仅源图引用可指向用户给定的外部文件。记录不触发网络、代码或自动搜索。schema 与语义校验一起验证版本关系和路径。

临时文件放在本次私密工作目录的受控临时区；脚本清理自己创建的文件，不扩大到宿主工具的其他文件。验收通过、成图成功保存且记录提交成功后才宣布该版本可用；中断不破坏旧记录，不把未登记候选作为当前版本。按需附加文件另存，生成或重建提示词如实标明来源。

## 7. README 可以承诺什么

明确说明一张含 1–6 人的照片、可补一句场景、一次成图、自然语言修改；每张图单独判断视觉方向。说明当前经验证的 Codex/平台/依赖和输入格式，所需图像处理能力、当次知情授权、生成式人物与中文仍可能失败、失败不交付为成品且不自动重试。

不声称完全本地、免费无限次、零错字、人物像素不变、任意照片必成功或跨所有客户端兼容。演示样片标注来源及被测版本；不得把曾通过视觉方向评审的原型改称正式版本验收成绩。三张真实验收照片保持私密，不默认进入展示。

## 8. 公开发布前的完成条件

1. 正式运行文件完成，技能校验通过，无占位内容、失效相对引用或未授权外部资源。首发在声明的平台/Python 组合验证本地脚本；生成式完整流程至少在一个明确标注版本的目标 Codex 环境跑通。
2. 安装压缩包与允许名单一致；从干净目录安装，实际可发现、调用、自检、完成生成和修改；卸载或更新不影响成图。参考环境 lock 可重建，兼容范围与真实 CI 结果一致。
3. 满足已确认的完整验收合同：视觉五项各 ≥4/5；18 次首次生成 ≥16 次成功且逐输入有成功；修改与失败矩阵全部通过；无错误候选被误交付。
4. 原创代码/文档 MIT，合成测试照及展示图逐文件标注许可和来源。已批准的六张照片 CC0 不自动扩展至其他生成图片，新增资产逐项登记；依赖许可证随附所需通知。未知或不允许的资产许可阻止发布。
5. 检查将公开的代码、全部分支/标签历史、附件、README、议题/评论、PR、CI 日志及制品；无私人照片、场景文字、提示词、私人路径、密钥或来源不明素材。仅 `.gitignore` 不能证明历史干净。对含私密内容的历史先给出具体处理方案，不擅自重写或发布。
6. 首页效果展示完成真人审阅，覆盖至少三种不同场景的艺术指导；全部使用许可清楚的非真实人物公开素材。发布统计如实说明样本与环境限制。
7. 将通过的候选提交、包文件、测试结果与发布文案交由仓库所有者执行或明确授权公开。当前仓库保持私有；确认本提案不等于批准切换可见性、发布制品或使用私人照片做营销。

实现时可自动完成授权范围内的编码、隔离环境检查和打包准备；只有发布本身需要明确外部发布授权。公开前清单是具体检查义务，不是声称已经完成的检查结果。
