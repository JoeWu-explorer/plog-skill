# README Plog 展示素材

创建日期：2026-09-07。用户要求制作不同类型的展示图，补充人文题材，并展示自动文案、色调、氛围和排版的前后变化。本目录按该用途制作和使用。

## 第一轮：六组原图编辑对照

| 目录 | 类型 | 自动配文 |
| --- | --- | --- |
| `together/` | 人物相聚 | 茶还没凉，话还没聊完。 |
| `craft/` | 人文手艺 | 一挑一压，慢慢成形 |
| `cat/` | 宠物陪伴 | 今天的安排：晒太阳。 |
| `coast/` | 山海旅行 | 山海很大，今天很慢 |
| `city/` | 城市街景 | 雨落下来，街慢下来 |
| `table/` | 食物日常 | 早餐还热，慢慢吃吧 |

每个目录的第一版均包含 `before.png` 与 `after.png`：

- `before.png` 是内置 image_gen 原创生成的无字照片，人物、场景均为虚构。它们直接复制自生成结果，未额外调暗、去色或修坏来夸大前后差异。
- Agent 根据一句示例需求及当前仓库的艺术指导，自行选择配文、色调、氛围和文字位置，再将该原图的归一化副本交给内置 image_gen 做一次实际图片编辑。
- 第一版每个案例只有一次原图生成与一次编辑调用，没有从多轮成图中挑选最佳结果。未用 HTML、Pillow 或其他绘图方式后贴字／调色。
- 已运行 photo-dialogue 的 inspect / prepare；编辑后逐对查看原图与候选，检查文字、全景和可见主体特征。六组都以 390 CSS px 宽对照查看，两组人物另以 540 CSS px 放大核对。
- 核对后用 revision_record.py append 保存 v001，并通过 delivery 取回同版 PNG。仓库 `after.png` 为该已保存 PNG 的副本；导出仅清理元数据，不另改画面。
- 六份独立版本记录保存在本机作品目录中，未把用户目录绝对路径写入仓库。原图在编辑前记录 SHA-256，保存时与原文件核对。

生成编号、示例需求、自动决策、原图和成图哈希见 [cases.json](cases.json)。原图生成与编辑采用 OpenAI 内置 image_gen；视觉查看由当前 Agent 在 Codex 浏览器中执行。这是本次合成素材演示的检查记录，不是所有 Agent／服务的兼容性认证，也不替代完整 Plog 视觉矩阵或产品负责人的评分。生成式编辑可能改变细微纹理，不承诺逐像素保真。

## 第二轮：加强文字与排版张力

用户统一提出“字和排版要更有张力一点，让用户更高感知我们的产品”。Agent 保留六张既有配文与光色，自行设计每张的语义重点、字形、尺度和阅读节奏；每张以 v001 的清洁副本做一次内置 image_gen 编辑，共六次，无自动重试。

| 案例 | 决策 | 当轮展示 |
| --- | --- | --- |
| 人物相聚 | 小字起句，宽幅浓墨展示字落句 | `together/after-v2.png`，v002 |
| 人文手艺 | 右侧主次字块呼应竹编纵横节奏 | `craft/after-v2.png`，v002 |
| 山海旅行 | 天空中的舒展笔势与小字形成尺度差 | `coast/after-v2.png`，v002 |
| 城市街景 | 米白双列竖排，大小错位 | `city/after-v2.png`，v002 |
| 宠物陪伴 | 新候选移动了椅背左侧边缘，超出排版范围 | 沿用 v001 |
| 食物日常 | 新候选向下移动杯子，超出排版范围 | 沿用 v001 |

核验同时对照原图、v001 和候选，六组均按 390 CSS px 宽查看，人物相聚与人文手艺另在 540 CSS px 宽对照原图。四张通过本次代理核验后由 revision_record.py append 保存 v002；原图与 v001 均保留。另两张存为各目录的 `candidate-v2-not-approved.png`，未写入接受版本、未放入主 README，不作为通过案例。

本轮艺术指导来自 alpha.4 之后的未提交工作区，文档哈希与各案例历史见 cases.json；不把修改倒记为已发布版本的能力验证。代理核验不是产品负责人的正式视觉验收。

README 通过 Markdown／HTML 并排引用实际原图和成图，不使用重新生成的“拼图”代替真实对照。顶部引用人物、山海与街景作品；当前图片版本见 cases.json。

## 使用范围

资产清单中的 `PROJECT-DISPLAY` 表示本次用户要求的项目 README 展示用途；不代表 CC0、MIT 图片授权或向第三方授予通用再分发权。代码／文档的 MIT 与既有测试照片的 CC0 不自动覆盖本目录图片。全部素材逐文件登记在 [资产清单](../../docs/assets.json)。

本目录只用于项目展示，不进入 Skill 运行包。alpha.4 发布清单继续记录其发布当时的测试状态，本轮示例不倒填为发布前成绩。

## GitHub 首页排版与预览文件

首页使用 GitHub 原生标题、链接图片与折叠区块。首屏三张成图等高排列；正文用四组无边框双列作品墙展示八类成图，原图和创作指令在组内展开。另保留一组默认可见的等宽前后对照。安装命令和使用示例直接显示；没有重新生成、裁切或修改图片像素。

第一轮六组原图与当前成图另保存同名 `.webp` 预览，由 cwebp 无损编码生成；已逐张验证解码后的 RGB 像素与 PNG 一致，未缩放、裁切、后贴字或改变色彩。12 个当前预览总大小从 PNG 的 30,395,344 字节减少为 21,327,180 字节（约 29.8%）。首页嵌入 WebP，点击图片打开对应 PNG；原文件及旧版仍保留。所有预览沿用原素材的 PROJECT-DISPLAY 用途，逐文件登记在资产清单。

## 第三轮：统一画内句末标点

用户要求画内配文不以句号收尾，保留问号与感叹号。人物相聚、宠物陪伴及风格示意页的三张图和作品墙含句末句号；另外四类当前成图原本就没有句末句号，保持原文件。

六张先各进行一次内置 image_gen 定向编辑。整图修改出现非目标细节变化，作品墙仍有遗漏，未将这些候选用于展示或接受版本。随后向用户说明局部修补方式，用户回复“发布吧”后，以原展示图为底，仅在句号附近做本地修补：人物与宠物使用相邻背景克隆及融合，其余使用局部修复。逐张核对文字、局部边缘及整图，人物与宠物同时对照原图和所选旧版，按 390 px 宽检查阅读效果。已验证每张最终文件修补遮罩以外的 RGB 像素与所选底图完全相同。

- 人物相聚保存 v003，展示 `together/after-v3.png`
- 宠物陪伴保存 v002，展示 `cat/after-v2.png`
- 风格示意使用 `sea-plog-v2.png`、`street-plog-v2.png`、`breakfast-plog-v2.png` 与 `hero-v2.png`
- 原图、历史成图及历史生成提示词均保留；当前 README 链接改为无句末句号的版本

本次是用户同意的局部图片维护，不是 Skill 的自动生成能力测试，也不把本地修补说成图像模型单次输出。处理方法、区域、旧版和新版哈希见 [标点修订记录](punctuation-revision.json)。本次授权不作为未来用户或其他照片的永久授权。
